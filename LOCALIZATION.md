# App languages

The app initially follows the device’s preferred language. Login has no language picker. Users can choose an override in Settings; that explicit choice takes precedence on subsequent launches. Preparing and caching the device language does not save an override, so later launches continue to follow device-language changes until the user makes a choice. On iOS 18 and later, the list is discovered using Apple Translation and includes the language pairs available on that device for the catalog's English and French originals. Apple may require a language-pack download and user consent. No external translation account or key is needed. This is not a promise of support for every language worldwide. iOS 17 retains the original English/French choices; automatic translation requires iOS 18.

`DiamaPay/utils/AppStrings.swift` is the global copy catalog. Each named entry specifies its original text, source language, and optional built-in French translation. Use its named properties or functions in views. Interpolated values use `__ARG_0__` placeholders; runtime names, phone numbers, account numbers, amounts, and backend messages are inserted after translation and never sent to the translation engine. Keep protocol identifiers and navigation keys out of the catalog.

`AppLanguageStore.swift` saves the selected language and caches translated entries in UserDefaults. Both the source text and source language are part of cache validation, so edited copy and corrected language metadata are translated again. Legacy cache entries without source-language metadata are regenerated. The language picker also offers Refresh translations; the existing translated interface is retained until preparation succeeds, including when the user cancels a refresh. A language changes only after its entire missing catalog has been prepared. Failure and cancellation preserve the prior selection, and late results from cancelled requests are ignored. Language work runs at the app root without recreating navigation or forms. Downloads may be needed on first launch because the existing catalog has both French and English originals.

`AppLanguagePicker.swift` discovers supported languages, offers search, prepares translations in batches, validates placeholders, and provides cancellation and failure feedback. SwiftUI receives the selected locale and text direction. Supported right-to-left languages use right-to-left layout. The Terms screen labels automatic translations and lets users inspect the original French text; automatic translations have not been professionally reviewed.

Covered: every SwiftUI screen and shared view in the app, including registration, sign-in and PIN recovery, profile, beneficiaries, account links, all transfers, vouchers, mobile money, QR payment, bills and DSD, standing instructions, sponsors, savings, loans, food ordering and complaints, transaction lists and receipts, limits, comments, help, terms, and security/biometric settings. Model-generated transaction descriptions, local network errors, and native security prompts also use the catalog. All 130 SwiftUI view declarations observe language changes. Branding, identifiers, currency codes, symbols, and numeric formats remain literal where appropriate.

Controlled options preserve their source values and API tags through `AppStrings.original`; their visible labels use `AppStrings.option`. Navigation IDs, payment processing codes, status filters, recipient identifiers, and user-entered content keep their underlying values. Known local error messages can be displayed in the selected language without changing `APIError.message`. Unknown server text, restaurant/provider/customer names, and personal data are shown as received. System permission dialogs follow iOS language settings. PDF receipts retain their existing fixed layout; verify long translations before relying on receipt rendering in a new language.

Verification: select another supported language on a physical iPhone running iOS 18+, approve any language download, verify Login and Settings, transfer forms and confirmations, history filters, pagination, detail receipts, CSV/PDF exports, and terms/original switching. Switch to a supported right-to-left language and check layout. Cancel a download, retry a failed preparation, and relaunch after a successful selection. Apple Translation execution and language downloads need device testing; syntax/type checks and model tests do not establish visual correctness or translation quality.

Regression tests in `DiamaPayTests/AppLocalizationTests.swift` cover source option/API value preservation and catalog placeholder integrity, as well as open language identifiers, text direction, placeholder isolation/reordering, cancellation, incomplete preparation, persistence, and reuse of cached translations.
